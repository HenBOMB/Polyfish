# Literature, rules, and asset audit

## Tribes literature

Search snapshot dated 2026-11-18. The seed works were the [AIIDE framework paper](https://doi.org/10.1609/aiide.v16i1.7438), [MCTS pruning](https://ceur-ws.org/Vol-2862/paper27.pdf), and [portfolio MCTS and MAP-Elites](https://doi.org/10.1109/cog52621.2021.9619094). Searches used exact titles, DOI lookups, the authors' [GAIG project page](https://gaigresearch.github.io/projects/Tribes), and the OpenAlex forward filter `cites:W3094507327|W3165381964|W3152887548`. The index returned 22 unique records, including cross-citations among seed papers. Their titles and available abstracts were screened, with the [query result](results/openalex-forward.json) retained. The seed papers' reference sections and the project bibliography supplied backward links. Google Scholar returned HTTP 403 for the exact-title query, so this snapshot has partial database coverage.

Include studies that run experiments on Java Tribes or analyze those experiments directly. Record separate papers that transfer the idea to other games or cite it as background. The included work recovered so far is:

- **Perez-Liebana et al. (2020)** introduce a Java state-copy and advance interface, with rule-based, one-step, Monte Carlo, MCTS, and Rolling Horizon Evolution agents. The reported Capitals tournament used fully observable 11×11 Xin-Xi versus Imperius maps at roughly half water, 25 maps and 20 repetitions per map, and 2,000 advances per planning decision. The reported RHEA win rate against MCTS was 63%. The source includes level seeds and Java tournament configuration. [Paper](https://doi.org/10.1609/aiide.v16i1.7438) · [Source](https://github.com/GAIGResearch/Tribes)
- **Hsu and Perez-Liebana (2020)** investigate move pruning and domain knowledge to address high branching factors in Tribes. Read this as a follow-up experiment in the original domain. Its search variants and action ordering are separate from the v1 bot presets. [Paper](https://ceur-ws.org/Vol-2862/paper27.pdf)
- **Perez-Liebana et al. (2021)** evaluate portfolio MCTS with progressive unpruning and use MAP-Elites to find varied, competitive Tribes play styles. The relevant continuation is the use of a forward model and shared game actions for agents with different search and behavior objectives. [Paper](https://arxiv.org/abs/2104.08641)
- **Gaina (2021)** discusses the original Tribes RHEA experiments in her thesis. Treat this as extended description of the same experiment. [Dissertation, §7.2](https://rdgain.github.io/assets/pdf/papers/gaina2021phd.pdf)

Boundary cases include [Dockhorn et al.](https://ieee-cog.org/2021/assets/papers/paper_271.pdf) and the two Elastic MCTS studies, whose test environments use Stratega, and [Fernandes et al.](https://arxiv.org/abs/2112.04406), whose persona experiment uses Grave Rave. [Nam et al.](https://doi.org/10.1007/978-981-92-5641-9_34) cite Tribes as related work while evaluating a separate platform. Check all unresolved full texts and their citation paths before treating the search as exhaustive.

## Adjacent implementations and adoption

- **Java Tribes** is the historical forward-model reference. The public source at `015a551d1a6be69b5931788fcc418e4c51eb8ea1` predates the AIIDE publication and exposes the original agent families. The repository did not list an explicit license during this audit. Polyfish uses an independent Rust implementation based on the published algorithm descriptions. The Java pilot builds locally from a separate checkout. [Java Tribes](https://github.com/GAIGResearch/Tribes)
- **tribes-rl** ports Java Tribes rules to C for PufferLib. Its maintainers document golden trace checks against the Java implementation. It is a valuable comparator for the historical rules and test approach. [Repository and validation](https://github.com/pham-tuan-binh/tribes-rl)
- **PolyEnv** documents a C++ engine with Python bindings for agent training, MCTS, and saved games, with 12 standard tribes. Benchmark coverage and historical-agents parity require separate validation. [PolyEnv](https://polyenv.readthedocs.io/en/latest/index.html)
- **Polyfish adoption** includes public GitHub forks such as `HarkushaVlad/Polymatrix`. Fork lineage confirms source ancestry. It does not establish what ran in production or support attribution to bots whose authors refer only to an unnamed Rust engine. [Public fork history](https://github.com/HenBOMB/Polyfish/forks)

## Reference versions and workflows

The commercial workflow reference is Midjiwan's **2.16.8** build, identified in the installed macOS app wrapper and the publisher's version history. Polyfish generated matches use its internal rules ID **115**, recorded independently. Version matching, generated-map identity, and comprehensive rules agreement with the commercial binary remain unverified. Official documentation supplies the Might capital-capture rule. [Version history](https://apps.apple.com/us/app/the-battle-of-polytopia/id1006393168?platform=watch) · [Might format](https://polytopia.io/World%20Championship/)

The browser checklist covers selecting a map and opponent, inspecting explored and unexplored tiles, selecting a unit and destination, inspecting economy options, opening research, ending a turn, saving, and stepping over replay commands. Polyfish exposes these as board buttons, contextual actions, and local files. Java Tribes documents its own launch configuration and controls. Midjiwan documents pass-and-play, army training, exploration, combat, and a tech tree that exposes resource, unit, and building unlocks. These are workflow targets. A controlled side-by-side pass through the commercial UI is still pending. [Java Tribes interface](https://github.com/GAIGResearch/Tribes) · [Midjiwan's gameplay overview](https://polytopia.io/polytopia-switch/)

The forced-spawn tests follow the published push rules for standard land units. They cover an unmoved Catapult after a different unit leaves its city, movement and ranged attack directions, besiegers, and blocked destinations. The center tie cases use the isometric board's south direction and the midpoint between tiles on even-sized maps. Direct measurements in version 2.16.8 are still pending. [Midjiwan's giant push example](https://polytopia.io/news/strategy-tip-4/) · [Push rules and worked example](https://docs.google.com/document/d/1C3nQm6SnRFc5pkWMy_WOj8LRosuj2XlINCmCoDfswn4/edit)
