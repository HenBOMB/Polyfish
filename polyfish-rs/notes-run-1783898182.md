## ⚠ 2026-07-13 UPDATE: the entire Elo eval was invalid — root cause found

`gumbel_mcts.rs::next_root_hash_for` applied the chosen move to the game it
was handed, assuming a per-call clone. self_play's Brain path does pass a
clone (training was unaffected), but the ARENA passes the real game — so every
Gumbel move was applied TWICE. Consequences, all now explained by this one bug:

- **EndTurn double-apply consumed the opponent's entire turn.** In every
  arena game with a Gumbel player, the opponent NEVER MOVED (verified by
  trace: bots got ~2 select_move calls per 30-turn game, the game loop went
  p1→p1→p1…). "Beats every bot 100%" measured a one-player game.
- **Model-vs-model exact 50-50s**: both sides Gumbel → whoever moved first
  locked the other out; side-swapped pairs therefore split 1-1 by
  construction. NOT spawn advantage, NOT equal strength — pure artifact.
- **The execute-error spam** (Harvest "No resource", Research "insufficient
  stars") was the second application of already-played moves failing — not
  the AI attempting illegal moves.
- **The BurnForest star-debt panic** was the second application spending
  stars the first had already spent.

Fix: `next_root_hash_for` now clones internally (patch). After the fix,
greedy vs a fresh init model: greedy plays ~230 moves/game, scores ~4.3k, wins
2/4 with eliminations — consistent with in-loop anchor games (model ~21% wr).

**Every number in elo_ratings.json is garbage; delete matches.jsonl and
re-rate all checkpoints from scratch with the fixed arena.** True checkpoint
strength vs greedy at 30 turns is currently UNKNOWN (in-loop 21% at caps
10-15 suggests the model may genuinely be below greedy still).

24 iterations overnight, ~100 games each, CPU candle eval, Gumbel k=16 @ 128
mcts-iters, Imperius mirror on Tiny Drylands, FOW on. Elo eval ran 2026-07-13
(elo.log / elo_ratings.json).

## Headline results

1. **No measurable strength gain iter6 → iter24.** All four checkpoints rated
   ~965–980 Elo. Every model-vs-model arena match ended in an EXACT 50-50 seed
   split (7/7 matches) — the winner of each game pair was decided by
   spawn/map, not by which model played. Head-to-head average scores were
   near-equal both sides (~3.4–3.9k) with no newer-beats-older trend.
2. **The training CSV "improvements" were mostly artifacts.** Score, builds,
   moves/game etc. jump at iters 8, 14, 21 — these track the max_turns
   curriculum stages (10→15→20→30, confirmed by which spt_tN columns go
   nonzero), not learning. Longer leash → bigger numbers.
3. **The run never actually did self-play.** Every logged iteration ran
   `100% greedy-anchor games` (anchor gate: winrate vs greedy stayed 16→24%,
   graduation needs 55%). So all training data was model-vs-greedy, and the
   model lost ~75% of those games (score-at-cap adjudication at short caps
   favors greedy's instant farming). Decisive-game count rose 6 → ~65 per 100
   over the run — the model increasingly *eliminates* greedy — but winrate
   barely moved because most games are still decided on score at the cap.
4. **Value R² flat at ~0.43–0.48 all night.** Consistent with (3): outcome
   labels are dominated by adjudication/spawn effects the value head can't
   compress further.
5. **52% of Elo arena games crashed** (BurnForest star-spend panic, see
   fixes). Some pairings rated on as few as 2 games. Arena mislabeled the
   panics as "transient GPU/backend error".
6. **Network parity Rust(candle) vs Python(PyTorch): OK** — max|diff| ~1e-4
   across all 7 heads on a fresh init model (channels=142, player_dim=16,
   map=11). Arch-mismatch hypothesis ruled out on this machine's code; re-run
   on the pod against the trained checkpoint to fully close it.

## Fixes applied (patch: `star-guards-arena-parity.patch` at repo root)

- **Gumbel root-advance double-apply** (the big one, see update above):
  `next_root_hash_for` clones the game before hashing the next root.
- **Arena `ARENA_TRACE=1`** env var: per-ply trace (turn, pid, move) — the
  instrumentation that found the double-apply; kept for future debugging.
- **Star-spend guards**: `require_stars()` in `src/actions/mod.rs`; BurnForest,
  GrowForest, EstablishEmbassy, EnchantAnimal now reject gracefully instead of
  panicking mid-game. (Harvest/Summon/Build/Research/Upgrade already validated.)
- **Arena**: panics now print the real panic message per dropped seed; per-game
  result lines (`game seed=… config1 (elimination) scores A-B`); summary says
  "dropped after in-game panics".
- **CSV**: new `max_turns` column (self_play METRICS + training_log.py HEADER;
  existing files auto-migrate) so curriculum stages are visible in the log.
- **Ladder**: added `heuristic1024` top rung + cross-links in
  `rate_checkpoints.sh` so checkpoint ratings stay discriminative.
- **Parity test**: `cargo run --release --bin parity_dump [model]` then
  `.venv/bin/python3 parity_check.py [model]` — run after every arch change.
